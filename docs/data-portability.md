# データ可搬性

## 方針

初期版の正本はSupabase PostgreSQLである．

将来のバックアップや分析のため，ユーザー単位でデータを取り出せる構造を維持する．

## バックアップ

将来的に別Supabase Projectや別サービスへ移行したい場合に備え，以下を可能にする設計を維持する．

* ユーザー単位のJSONエクスポート
* ユーザー単位のCSVエクスポート
* Excelエクスポート
* SQL dumpまたはSupabase backupからの復元

初期版ではバックアップUIは実装しない．

ただし，テーブルがユーザー所有単位で分離され，`user_id` により抽出しやすい構造にする．

## Googleアカウント変更

Googleアカウント変更は初期版の必須要件ではない．

将来対応する場合は，旧ユーザーIDのデータを新ユーザーIDへ移管する管理用処理を別途設計する．

ブラウザにService Role Keyを渡して移行する設計は採用しない．

## Excel

Excelは正本ではなく，将来の一方向エクスポート形式として扱う．

Excelインポートや双方向同期は初期版では実装しない．
