# 要件整理

## 目的

iOSアプリ「筋トレMEMO」の不満点を解消し，スマートフォンを主対象としたWeb完結型トレーニング記録アプリを作成する．

自分一人だけでなく，3〜5人程度にも使ってもらう想定である．

ユーザー側の操作はできるだけ簡単にする．

## 基本方針

| 項目 | 方針 |
|---|---|
| 利用端末 | iPhoneを最優先し，PCにも対応する |
| アプリ形態 | Web完結型 |
| Hosting | Vercelを第一候補とする |
| 認証 | Supabase Auth + Google OAuth |
| ユーザー向けProvider | Googleのみ |
| 正本 | Supabase PostgreSQL |
| DB | Supabase PostgreSQL |
| RLS | 必須 |
| Excel | 正本ではなく，将来のエクスポート形式 |

## ユーザー体験上の優先度

| 優先度 | 項目 | 理由 |
|---|---|---|
| 高 | Googleログインのみ | 利用者に追加設定を要求しないため |
| 高 | 大きいメモ欄 | 現行アプリの最大不満点であるため |
| 高 | 前回メモの即時表示 | トレーニング中のフォーム確認に直結するため |
| 高 | iPhone Safariでの入力しやすさ | 実利用時の主端末であるため |
| 高 | ダークモード | トレーニング中の視認性に関わるため |
| 高 | ユーザー分離 | 3〜5人利用でも他人の記録を見せないため |
| 中 | PCでの閲覧と設定 | 履歴確認や種目管理を効率化するため |
| 中 | 最高記録と推定1RM | 初期分析機能として有用であるため |
| 低 | 完全オフライン対応 | 初期版では通信前提でよいため |

## 維持するUI要件

月間カレンダーをメイン画面とする．

今日，トレーニング実施日，日付タップ，左右スワイプ，月移動ボタンを実装対象とする．

部位フィルターは，すべて，胸，背中，脚，肩，腕，腹筋，有酸素運動を用意する．

ダークモードを維持する．

iPhone Safariを最優先し，PCにも対応する．

入力欄は16px以上にする．

ピンチズーム禁止はしない．

大きいタップ領域を維持する．

## データ要件

初期テーブルは以下である．

* `profiles`
* `body_parts`
* `body_part_preferences`
* `exercises`
* `workouts`
* `workout_exercises`
* `sets`
* `exercise_settings`

主キーはUUIDを使用する．

ユーザー所有データには `user_id` を直接持たせる．

過去記録が存在する種目は物理削除しない．

## 初期部位

初期部位は全ユーザー共通マスタとする．

* 胸
* 背中
* 脚
* 肩
* 腕
* 腹筋
* 有酸素運動

## 初期種目

新規ユーザー登録時に，ユーザーごとの初期種目を作成する．

初期種目作成はDB triggerを第一候補とし，アプリ起動時の冪等RPCで補完する．

## 現在のMVP

現在の成功条件は以下である．

```text
Googleログイン
↓
Supabase Session取得
↓
profiles確認
↓
初期種目確認
↓
日付別Workout表示
↓
トレーニング保存
↓
ログアウト
```

DB schemaはmigrationで再現可能にする．

Workout CRUDは，初期MVPとして1種目単位の作成，選択日一覧表示，削除から実装する．
